# church-report 프로젝트 Claude Code 이전 계획서

이 문서는 Claude Code가 읽고 **순서대로 실행**하기 위한 것이다. 사용자는 보스턴 온누리교회 행정 간사이며 IT 전공자가 아니다. 모든 설명은 한국어로, 기술 용어는 쉬운 말로 풀어서 한다.

## 진행 규칙 (이전 작업 내내 적용)
- `⏸ 사용자` 표시가 있는 단계에서는 **멈추고** 사용자가 할 일을 짧고 구체적으로 알려준다. 사용자가 "했어"라고 답하면 이어서 진행한다.
- 각 단계가 끝나면 무엇을 했는지 한두 줄로 보고한다.
- 명령이 실패하면 임의로 다른 방법을 시도하지 말고, 오류 내용을 쉬운 말로 설명하고 멈춘다.
- `clasp create-deployment`(또는 `clasp deploy`)를 **배포 ID 없이 실행하지 않는다.** 배포 ID 없이 실행하면 새 URL이 생겨 교회 전체 서비스가 끊긴다.
- `git push`는 변경 파일 목록과 요약을 보여주고 사용자가 "푸시해"라고 한 뒤에만 한다.
- 비밀번호는 화면에 출력하지 않는다.
- 이 저장소는 **Public**이다. 비밀번호가 들어간 파일을 커밋하지 않는다.

## 프로젝트 폴더와 준비물
프로젝트 폴더는 **`/Users/bostononnuri/Claude Code/예배 출석 보고 시스템`** 이다. Claude Code는 이 폴더에서 실행 중이다. 폴더 이름에 띄어쓰기가 있으므로 **모든 경로는 따옴표로 감싼다.** 아래에서 `$ROOT`는 이 폴더를 뜻한다.

사용자가 이 폴더에 미리 넣어둔 파일:
- `CLAUDE.md` — 프로젝트 규칙
- `project_knowledge.md` — 아키텍처·변경이력 문서 (비밀번호 없는 버전)
- `보스턴온누리교회_디자인가이드.html`
- `사용자가이드.html` — 없으면 건너뛴다
- `이전계획.md` — 이 문서

백엔드 코드 파일은 필요 없다. 3단계에서 Apps Script 편집기에서 직접 내려받는다.

시작하자마자 `pwd`로 현재 위치가 위 폴더인지 확인하고, 아니면 멈추고 사용자에게 알린다.

## 0단계 — 도구 확인
다음이 설치되어 있는지 확인하고 버전을 보고한다: `node`, `npm`, `git`, `gh`(GitHub CLI), `brew`(Homebrew).
- `gh`가 없고 `brew`가 있으면 `brew install gh`로 설치한다. `brew`도 없으면 사용자에게 알리고 멈춘다.
- `node`가 없으면 멈추고 알린다 (Claude Code가 돌고 있으면 보통 있다).

## 1단계 — 이 폴더를 GitHub 저장소와 연결
폴더에 이미 파일이 있어서 `git clone`을 바로 할 수 없다(빈 폴더에만 된다). 저장소를 임시 폴더에 받은 뒤 숨김 폴더 `.git`까지 포함해 이 폴더로 옮긴다:
```bash
ROOT="/Users/bostononnuri/Claude Code/예배 출석 보고 시스템"
rm -rf /tmp/church-report-clone
git clone https://github.com/bostononnuri-admin/church-report.git /tmp/church-report-clone
shopt -s dotglob
mv /tmp/church-report-clone/* "$ROOT/"
rmdir /tmp/church-report-clone
cd "$ROOT"
git status
git log --oneline -5
```
`git status`에서 `index.html`·`logo.jpg`는 추적 중이고, 준비 파일들은 "Untracked"로 보이면 정상이다. 루트에 `index.html`과 `logo.jpg`가 생겼는지 확인한다. 이 두 파일은 GitHub Pages가 서빙하므로 **절대 옮기지 않는다.**

## 2단계 — 파일 배치
```
예배 출석 보고 시스템/            ($ROOT)
├── index.html, logo.jpg          (그대로)
├── backend/                      (3단계에서 clasp이 채움)
├── docs/
│   ├── project_knowledge.md
│   ├── 보스턴온누리교회_디자인가이드.html
│   └── 사용자가이드.html        (있으면)
├── CLAUDE.md
├── CLAUDE.local.md               (아래에서 생성, git 제외)
├── .gitignore
└── deploy-backend.sh             (4단계에서 생성)
```
1. `mkdir -p backend docs`
2. `CLAUDE.md`와 `이전계획.md`는 루트에 그대로 두고, `project_knowledge.md`·디자인가이드·사용자가이드를 `docs/`로 옮긴다(`mv`).
3. `.gitignore`를 만든다:
   ```
   CLAUDE.local.md
   .claude/settings.local.json
   .clasprc.json
   .DS_Store
   ```
4. `CLAUDE.local.md`를 만든다. 내용은 아래 틀이고, 비밀번호 값은 **사용자에게 물어서** 채운다 (⏸ 사용자: "관리자 비밀번호를 알려주세요"). 수정모드 비밀번호는 모르면 비워둔다.
   ```
   # 비밀 값 — git 제외. 절대 커밋 금지.
   - 관리자 비밀번호 (ADMIN_PW): ______
   - 수정모드 비밀번호: ______
   ```
5. `git status`로 `CLAUDE.local.md`가 "Untracked"에 **없는지**(gitignore가 먹는지) 확인한다.

## 3단계 — Apps Script와 연결 (clasp)
1. `npm install -g @google/clasp` 후 `clasp --version`으로 확인. 설치 후 `clasp --help`를 실행해 `create-deployment`, `clone-script`, `list-deployments`, `list-scripts` 명령 이름이 맞는지 확인한다. (버전에 따라 `deploy`, `clone`, `deployments`, `list`일 수 있다 — 실제 이름을 쓴다.)
2. ⏸ 사용자: 브라우저에서 https://script.google.com/home/usersettings 를 열고, **교회 구글 계정**으로 로그인한 상태에서 "Google Apps Script API"를 **켜기(On)**로 바꾸게 한다.
3. `clasp login` 실행 → 브라우저가 열린다. ⏸ 사용자: 교회 구글 계정(출석 보고 스크립트를 소유한 계정)으로 로그인하고 권한을 허용하게 한다.
4. `clasp list-scripts`로 최근 스크립트 목록을 보여주고, 출석 보고 시스템에 해당하는 것을 사용자에게 확인받는다 (⏸ 사용자). 확신이 없으면 사용자가 Apps Script 편집기 ⚙️ 프로젝트 설정에서 스크립트 ID를 복사해 알려주게 한다.
5. `$ROOT`에서:
   ```bash
   cd "/Users/bostononnuri/Claude Code/예배 출석 보고 시스템"
   clasp clone-script <스크립트ID> --rootDir backend
   ```
   `backend/` 안에 내려온 파일 목록을 보고한다 (보통 `Code.js` 또는 `코드.js` 하나와 `appsscript.json`). 루트에 생긴 `.clasp.json`은 커밋해도 된다(스크립트 ID만 들어 있음).
6. `clasp list-deployments`를 실행하고, 목록에 다음 배포 ID가 있는지 확인한다:
   `AKfycbzztaNejz8nkgug16NWI3lZtBlMSSTUHpTh0j4odURkmlWrqa67t0s8mvbaa70fGFS6_Q`
   **없으면 멈추고 사용자에게 알린다.** 이 ID가 교회에서 쓰는 실제 주소다.
7. 내려온 백엔드 코드에서 `function handleReport`, `function handleMonthlyReport`, `var SVC_ALIAS`, `var SVC_PERIOD`가 있는지 확인한다. 있으면 2026-10-31 개편 버전이 맞다. 없으면 멈추고 알린다.
8. `CLAUDE.md`는 이미 clasp 기준으로 작성되어 있다. "파일 구조"의 `backend/` 설명에 적힌 파일명(`Code.js`)이 실제 내려온 파일명과 다르면 그 부분만 고친다.

## 4단계 — 비밀번호를 코드에서 치우고, 배포 리허설
백엔드 코드 8행쯤에 `const ADMIN_PW = "..."` 로 비밀번호가 평문으로 들어 있다. 이 코드가 Public 저장소에 올라가면 안 되므로 Apps Script의 "스크립트 속성"으로 옮긴다. **순서가 중요하다: 속성을 먼저 넣고, 코드를 나중에 배포한다.**

1. ⏸ 사용자: Apps Script 편집기 → 왼쪽 ⚙️ **프로젝트 설정** → 맨 아래 **스크립트 속성** → "스크립트 속성 추가" → 속성 `ADMIN_PW`, 값은 관리자 비밀번호 → **저장**.
2. 사용자가 "했어"라고 하면 백엔드 코드에서 그 한 줄을 다음으로 바꾼다 (값은 코드에서 사라진다):
   ```js
   const ADMIN_PW = PropertiesService.getScriptProperties().getProperty("ADMIN_PW");
   ```
3. 같은 파일에서 `action === "ping"` 응답의 `version: "v4"`를 `version: "v5"`로 바꾼다. 배포가 실제로 갱신됐는지 확인하는 용도다.
4. `node --check`로 문법 검사 (`.js`가 아니면 `/tmp/check.js`로 복사해서 검사).
5. `$ROOT`에 `deploy-backend.sh`를 만들고 실행 권한을 준다(`chmod +x`). 폴더 경로에 띄어쓰기가 있으므로 스크립트 안의 `cd "$(dirname "$0")"` 따옴표를 빼지 않는다:
   ```bash
   #!/bin/bash
   # 백엔드 배포: 코드 올리기 → 기존 배포를 새 버전으로 갱신 (URL 유지)
   set -e
   cd "$(dirname "$0")"
   clasp push
   clasp create-deployment --deploymentId AKfycbzztaNejz8nkgug16NWI3lZtBlMSSTUHpTh0j4odURkmlWrqa67t0s8mvbaa70fGFS6_Q --description "${1:-update}"
   ```
   (3단계 1에서 확인한 실제 명령 이름이 다르면 그에 맞춘다. 배포 ID는 절대 빼지 않는다.)
6. ⏸ 사용자: "지금 백엔드를 배포하려고 합니다. 바뀌는 것: 비밀번호를 스크립트 속성에서 읽도록, 그리고 ping 버전 v5. 진행할까요?" 승인을 받는다.
7. `./deploy-backend.sh "ADMIN_PW를 스크립트 속성으로 이전"` 실행.
8. 검증 (둘 다 통과해야 한다):
   - `curl -sL "<Apps Script URL>?action=ping"` 응답에 `"version":"v5"`가 있는지.
   - `curl -sL "<Apps Script URL>?action=login&pw=<CLAUDE.local.md의 관리자 비밀번호>"` 응답에 `"success":true`가 있는지. (명령과 응답에서 비밀번호는 가려서 보고한다.)
   - 하나라도 실패하면 즉시 사용자에게 알린다. 로그인이 실패하면 1번의 속성 이름이 정확히 `ADMIN_PW`인지 확인하게 한다.
9. `CLAUDE.md`의 "배포 절차"와 "검증 방법"은 이미 이 흐름(`deploy-backend.sh`, ping version 확인, `node --check backend/*.js`)으로 적혀 있다. 3단계 1에서 확인한 clasp 명령 이름이 `create-deployment`가 아니었다면 `deploy-backend.sh`와 `CLAUDE.md`의 해당 명령 이름을 실제 이름으로 맞춘다.

## 5단계 — 문서 갱신 후 커밋·푸시
1. `docs/project_knowledge.md` 맨 아래 변경이력에 오늘 날짜로 한 항목을 추가한다: Claude Code 이전 완료, 저장소 구조, clasp 연결, ADMIN_PW 스크립트 속성 이전·ping v5 배포, 백엔드 파일명.
2. `git status`와 변경 파일 목록을 보여준다. **`CLAUDE.local.md`와 `.clasprc.json`이 목록에 없는지 다시 확인한다.**
3. ⏸ 사용자: "이 파일들을 GitHub에 올리려고 합니다 (index.html은 변경 없음). 푸시할까요?" 승인을 받는다.
4. `git add -A && git commit -m "Claude Code 이전: 저장소 구조·CLAUDE.md·백엔드 소스(clasp)·docs" && git push`
   - 푸시가 인증 오류로 실패하면 `gh auth login`을 실행하고 ⏸ 사용자에게 브라우저에서 GitHub 로그인을 하게 한 뒤 다시 푸시한다.
5. 1~2분 뒤 확인: `curl -s https://bostononnuri-admin.github.io/church-report/index.html | diff - index.html` — 파일 끝 줄바꿈 차이만 나오면 정상. (GitHub Pages는 저장소 내용만 보므로 로컬 폴더 이름이 한글이어도 사이트 주소는 그대로다.)

## 6단계 — 마무리와 최종 점검 보고
`이전계획.md`를 `docs/`로 옮기고(이전 기록으로 보관, 비밀 정보 없음) 커밋에 포함한다.

다음을 표로 정리해 사용자에게 보고한다:
- 저장소 위치와 폴더 구조
- 백엔드 파일명, 배포 ID, ping 버전
- GitHub에 올라간 파일 / 올라가지 않은 파일(CLAUDE.local.md)
- 앞으로의 작업 흐름 요약: 프론트 = 승인 후 git push / 백엔드 = 승인 후 `./deploy-backend.sh` / 둘 다면 백엔드 먼저
- 사용자가 직접 할 남은 일: claude.ai 프로젝트의 커스텀 인스트럭션에서 "예배 구분" 줄 갱신 또는 프로젝트 보관 처리

마지막으로 사용자에게 Claude Code 세션에서 `/context`를 쳐서 Memory files에 `CLAUDE.md`와 `CLAUDE.local.md`가 보이는지 확인하게 한다.
